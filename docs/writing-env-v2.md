## 0. このドキュメントについて

競争法の学術論文を、AI（Claude Code）併用で執筆するためのローカル環境の設計書。別チャットで単独レビューできるよう、前提を自己完結的に含む。

**一行要約：** プレーンテキスト（Quarto/Markdown）で原稿・文献・メモを統一キーで束ね、「文献を探して脚注に書く」作業を Claude Code に肩代わりさせる。引用の根拠は人間が検証済みのメモに限定し、捏造を構造的に封じる。

## 1. 背景と前提

### 1.1 執筆者・分野
- 分野は競争法（デジタル市場規制）。**脚注が極めて多く、引用の正確性が命綱**。
- 引用対象は日本語の法律文献・教科書・判例、英語の競争法二次文献、米国判決文（例：*United States v. Google*）が混在。

### 1.2 執筆形式（確定済み）
- 原稿は **Quarto（`.qmd`）**。中身は「YAMLヘッダ（設定）＋ Markdown本文」。
- 出力は Quarto が担当：PDFは裏で **MacTeX/LaTeX** を呼ぶ、Wordは `.docx`（XML群のZIP梱包）を自動生成、HTMLも可。
- Markdown採用の理由：AI編集との相性。差分（diff）が意味を持ち、構文が壊れにくい。Word の `.docx` は XML を ZIP圧縮したバイナリで、AIが差分編集できず不向き。
- **脚注・文献引用・相互参照は Quarto（Pandoc記法）で対応可能。** ただし `@キー`→CSL自動整形が実用に耐えるのは**欧米の二次文献（書籍・論文）に限る**。日本語文献および各国判例（Bluebook式の米国判例を含む）は、CSLでは正しく整形されないため**プレーンテキストで扱う**（§5.4）。

### 1.3 執筆者の既存習慣 ―― この設計で「変えない」前提
- **(A) メモはトピック単位。** 論文単位ではなく、1トピックについて複数の論文・判例を横断して抜き書きする（「この事件の何頁、この論文の何頁」）。
- **(B) 執筆は先に本文、後から脚注。** 本文を書き進めながら根拠が要る箇所に空脚注を打ち、後からメモを探して該当箇所を埋める。

### 1.4 既存インフラ
- VSCode + Claude Code + `CLAUDE.md` 運用に習熟。
- 新規アプリの導入・学習は避けたい（Obsidianは高機能すぎて締切の合間の学習コストが高い、と判断済み）。

## 3. 要件

### 3.1 機能要件
- **FR1 文献取り込み：** `pdfs/inbox/` の新規PDFを読み、命名規則でリネームして `pdfs/` へ移動し、`refs.bib` にBibTeXエントリを追記する。
- **FR2 トピック単位のメモ管理：** `notes/` にトピック単位のMarkdownを置き、1エントリ＝「**出典（二層）／引用（原文・必須）／メモ**」で抜き書きを蓄積する。
- **FR3 脚注穴埋めの半自動化：** 本文中の要出典マーカーを検出し、`notes/` から該当箇所を探し、**「出典」と「引用文」をセットで**脚注案として提示する。
- **FR4 引用整形：** 欧米の二次文献に限り、Quarto が `@キー` から引用と参考文献リストを自動生成する。
- **FR5 整合性チェック：** `notes/` 内の全 `@キー` を抽出し `refs.bib` と突合、孤児（対応エントリ無し）を報告する。
- **FR6 レンダリング前リント：** 出力前に本文の `要出典` 残数を検査し、残っていれば警告する。

### 3.2 非機能要件（安全性・正確性）―― 最重要
- **NFR1 情報源の限定：** Claude が引用の根拠にしてよいのは `notes/` に**実在する記述のみ**。自身の記憶から引用を生成しない。
- **NFR2 捏造の禁止：** 該当が無ければ「該当なし」と報告する。もっともらしい出典を補完しない。
- **NFR3 原典照合：** 書誌情報・頁・条文は原典と照合し、推測で埋めない。
- **NFR4 役割分担：** 逐語引用のコピペと、頁・年・条文の最終確認は**人間**。整理・リネーム・下書き生成は Claude。
- **NFR5 学習コストゼロ：** 既存の VSCode + Claude Code + Markdown で完結し、新規アプリを導入しない。
- **NFR6 冪等性：** 取り込みは `pdfs/inbox/` 投入→処理後に `pdfs/` へ移動する方式とし、重複実行で二重エントリを作らない。
- **NFR7 版管理・監査：** git で `*.qmd` / `refs.bib` / `notes/` を追跡する。Claudeによる一括編集（特に脚注穴埋め）の前後で commit し、diff を監査できる状態を保つ（NFR2の実効性担保）。`pdfs/` は `.gitignore`。

## 4. システム構成

### 4.1 ディレクトリ構成
```
paper-project/
├── paper.qmd          # 原稿本体（YAML + Markdown）
├── refs.bib           # 文献リスト（BibTeX、欧米二次文献が主）
├── pdfs/              # リネーム済みPDF（文献単位、.gitignore）
│   ├── inbox/         # ★未処理PDFの投入口。処理後に親へ移動
│   ├── wakui2018_antimonopoly.pdf
│   └── sensui2018_dokkin.pdf
├── notes/             # 抜き書きメモ（★トピック単位）
│   ├── self-preferencing.md
│   └── technical-tying.md
├── CLAUDE.md          # Claude Code への運用指示
└── .gitignore         # pdfs/ を除外
```

### 4.2 中核設計 ―― 統一キーによる紐付け
1文献に1つの**引用キー**（例 `wakui2018`）を与え、3対象を同キーで束ねる。

| 対象 | 命名・記法 | 組織の単位 |
|------|-----------|-----------|
| PDFファイル | `wakui2018_antimonopoly.pdf` | 文献単位 |
| BibTeXエントリ | `@wakui2018` | 文献単位 |
| メモ内の参照 | 出典行末の `[key: @wakui2018]` | トピック単位ファイルの中に出現 |

メモの組織単位はトピックに変えるが、各引用にキーを添えることで文献単位の `refs.bib` へ一本で戻れる。単位を変えても紐付けは生きる。

## 5. コンポーネント仕様

### 5.1 `pdfs/`（文献単位）
- 命名規則：`著者名+年_短縮タイトル.pdf`（半角英数）。
- 未処理PDFは `pdfs/inbox/` に投入し、取り込み処理後に `pdfs/` 直下へ移動（NFR6）。

### 5.2 `refs.bib`（文献単位、欧米二次文献が主）
- 1文献1エントリのBibTeX。`@キー`／CSL自動整形が実用になるのは欧米の書籍・論文。
- 例（英語二次文献 ― キーと著者が一致）：
```bibtex
@book{wakui2018,
  author    = {Wakui, Masako},
  title     = {Antimonopoly Law: Competition Law and Policy in Japan},
  publisher = {Edward Elgar},
  year      = {2018}
}
```
> ※例示は書式テンプレート。実際の書誌は原典照合のこと（NFR3）。

### 5.3 `notes/`（★トピック単位）
- **v1からの変更：** 当初は文献単位（`notes/wakui2018.md`）。執筆者の習慣（§1.3-A）に合わせ**トピック単位**へ。1トピック1ファイル。
- 1エントリの構造：**出典（二層）／引用（原文コピペ・必須）／メモ（所感）**。
- **出典行は二層で書く**：脚注に貼る人間可読の引用文字列（CSL非経由のプレーンテキスト）＋末尾に機械可読の `[key: @キー]`（紐付け・整合性チェック専用）。
- **「引用」は必須。** 空にしない。脚注案提示時にこの原文を併記することで、人間が誤マッチを一目で弾ける（Q2対策）。
- 判例など `refs.bib` にキーを持たないものは `[key: —]` とし、プレーンテキストのみで扱う。
- テンプレート例：
```markdown
# 自己優遇

## 自己優遇の定義
- 出典: 泉水文雄『独占禁止法』123頁  [key: @sensui2018]
  引用: 「自己優遇とは、プラットフォーム事業者が…」（原文コピペ）
  メモ: Paper2 §2の導入で使える

- 出典: United States v. Google, Doc.1436, at 45  [key: —]
  引用: 「…」（原文コピペ）
  メモ: 米国の定義アプローチ。判例なのでプレーンテキスト、EUと対比

## 自己優遇の競争上の害
- 出典: 泉水文雄『独占禁止法』88頁  [key: @sensui2018]
  引用: 「…」
  メモ: 反競争効果の類型化がここ
```

### 5.4 `paper.qmd`
- 執筆中、根拠が要る箇所に**要出典マーカー**（Quartoのインライン脚注）を打つ：
```markdown
本稿は、自己優遇が競争を害しうると考える。^[要出典: 自己優遇の定義]
```
- `^[...]` がインライン脚注、`要出典:` が「未充填」の目印。執筆者が書くのは**トピック名だけ**（習慣§1.3-Bを崩さない）。
- 穴埋め後（例）― **日本語文献・判例はプレーンテキスト**。`@` は残さない（`[key:]` タグも転記しない）：
```markdown
本稿は、自己優遇が競争を害しうると考える。^[自己優遇の定義につき、泉水文雄『独占禁止法』123頁。米国の整理として、United States v. Google, Doc.1436, at 45 も参照。]
```
- 欧米の二次文献をCSL整形に乗せたい場合（英語ジャーナル投稿等）のみ、脚注に `@キー` を残す運用も可。ただし投稿先スタイルと整合するCSLを用意すること。

> **決定が要る点（末尾の参考文献リスト）：** 日本語文献をプレーンテキストで脚注記載すると、Quartoの自動参考文献リストには載らない。①そもそも末尾リストを作らない（日本の法律論文では脚注完結が通例）／②作るなら YAML の `nocite` でプレーンテキスト文献を拾う、のいずれかを投稿先ごとに決める。→ §7

### 5.5 `CLAUDE.md`（追記分）
```markdown
## 文献を追加するとき（pdfs/inbox/ に新規PDFが入ったら）
1. inbox のPDF冒頭を読み、著者・タイトル・年・出版社/掲載誌を抽出
2. ファイル名を `著者名+年_短縮タイトル.pdf`（半角英数）にリネームし pdfs/ 直下へ移動
3. 同じキーでBibTeXエントリを refs.bib に追記（欧米二次文献が対象。既存キーがあれば重複させない）
4. 書誌・頁・条文は原典と照合。推測で埋めない
※ スキャンPDF等で書誌が読めない場合は、私に書誌情報を尋ねてから BibTeX化する（勝手に推測しない）

## メモを足すとき（notes/ はトピック単位）
- 既存トピックがあれば追記、無ければ新規作成
- 1エントリ = 「出典: <人間可読の引用文字列> [key: @キー]」＋「引用: 原文コピペ（必須）」＋「メモ: 所感」
- 判例等キー無しは [key: —]
- 書誌・頁は原典と照合。推測で埋めない

## 脚注の穴埋め（paper.qmd の要出典を埋める）
1. 本文から `^[要出典: <トピック>]` を全て抽出
2. 各トピックで notes/ を読み、該当エントリを特定
3. 脚注案は「出典（人間可読部分）」と「引用文（原文）」を必ずセットで提示。[key:] タグは脚注に転記しない
4. notes/ に該当が無ければ「該当なし」と報告。勝手に補わない
5. 複数該当は列挙して私に選ばせる。私が確認してから確定
※ 日本語文献・各国判例はプレーンテキストで転記（@ を残さない）。欧米二次文献をCSLに乗せる場合のみ @キー を残す

## 整合性チェック（取り込み時に毎回）
- notes/ 内の全 @キー を抽出し refs.bib と突合、対応の無い孤児キーを報告

## レンダリング前
- 本文の `要出典` 残数を grep して報告。残っていれば警告
```

## 6. ワークフロー仕様

### 6.1 文献取り込み（FR1）
1. PDFを `pdfs/inbox/` に入れる。
2. Claude Code に「取り込んで」と指示 → §5.5 の手順でリネーム＋移動＋`refs.bib` 追記＋孤児キー報告。
3. 人間が書誌を確認。スキャンPDFで読めなければ人間が書誌を口頭提供。

### 6.2 メモ追加（FR2）
1. 原典を読み、該当トピックのファイルに「出典（二層）／引用（逐語コピペ・人間）／メモ」を追記。
2. トピックが無ければ新規作成。

### 6.3 脚注穴埋め（FR3）―― 主目的
1. 執筆中、根拠が要る箇所に `^[要出典: <トピック>]` を打つ。
2. commit（穴埋め前）。
3. Claude Code に「要出典を埋めて」と指示 → マーカー全抽出 → `notes/` 検索 → **「出典＋引用文」をセットで提示**。
4. 該当なしは「該当なし」と報告（NFR2）。複数該当は人間が選ぶ。
5. 人間が確認して確定。commit（穴埋め後）。diff で監査（NFR7）。逐語引用の最終照合は人間（NFR4）。

## 7. レビューで決着した論点／残る決定

### 決着（v2に反映済み）
- **Q1 重複：** 許容。notes/ は作業素材であり、名寄せの実体は `refs.bib`＋`@キー` が担う。重複排除機構は不要。
- **Q2 照合：** 「厳密／曖昧一致」ではなく、脚注案で**出典＋引用文を併記**し人間が誤マッチを弾く方式に。統制語彙は不要（トピックが50超で再検討）。
- **Q3 日本法の引用：** 日本語文献・各国判例は**CSLを通さずプレーンテキスト転記**。CSL自動整形は欧米二次文献のみ。出典行の二層化で紐付けは維持。
- **Q4 git：** 導入。diffがMarkdown採用の主目的であり、一括編集の監査（NFR2）も兼ねる。`pdfs/` は除外。
- **Q5 同期：** 孤児キー検出タスクを CLAUDE.md に追加（取り込み時に実行）。
- **Q6 複数該当：** 人間が選ぶで確定。Q2の引用併記で選択は数秒。

### 残る決定（投稿先ごとに判断）
- **末尾参考文献リストの要否：** 日本語文献をプレーンテキストにすると自動リストに載らない。①作らない（脚注完結）か、②`nocite` で拾うか。日本の法律雑誌なら①、英語ジャーナルなら②が既定線。
- **英語投稿時のCSLスタイル：** 欧米二次文献を `@キー` で整形する場合、投稿先指定のスタイル（著者年式／脚注式）に合うCSLを用意する。

## 8. 将来拡張
- **Zotero 併用：** 英語DOI付き文献が増えたら Zotero で `refs.bib` を自動生成できる。日本の法律文献・判例（DOIなし）には弱いため当面は Claude にPDFを読ませる方が相性良い。乗り換えでなく増築（`refs.bib` が共通土台）。
- **JADE への転用：** curated な `pdfs/` と `notes/` はそのまま競争法RAG（JADE）のコーパス素材になり、**評価用の正解データ**にもなる。執筆がRAG構築の下ごしらえを兼ねる。

## 9. スコープ外
- PDF本文からの全文検索・意味検索（RAG）は含めない（JADE側の役割）。本設計の情報源は人間が抜き書きした `notes/` に限定（NFR1）。
- 判例・文献の自動ダウンロード（収集は人間）。
